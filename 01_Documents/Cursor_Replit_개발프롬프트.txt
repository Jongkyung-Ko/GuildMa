# GuildMaster 개발 프롬프트 (Cursor / Replit용)

너는 기존 GuildMaster 게임 프로토타입을 개선하는 시니어 게임 개발자이자 테크니컬 디자이너다.

## 가장 중요한 작업 원칙
1. 먼저 현재 프로젝트의 파일 구조, 사용 기술, 실행 방법, 기존 기능을 조사하라.
2. 기존 구조·디자인·게임플레이·입력 방식을 최대한 보존하라. 작동 중인 기능을 임의로 삭제하거나 전면 재작성하지 마라.
3. PC 키보드/마우스 조작을 유지하고, 기존 모바일 터치 지원이 있다면 반드시 유지하라.
4. 실제 구현 전에 현재 상태와 수정 계획을 간단히 보고하라. 불필요한 대규모 리팩터링은 하지 마라.
5. 이번 작업 범위에 없는 장기 기능(온라인 멀티플레이, 서버, 대규모 공성전, 완성형 길드 운영)을 한꺼번에 구현하지 마라.
6. 코드와 데이터 구조는 추후 길드 운영 시스템을 추가할 수 있도록 명확하고 모듈화하되, 초기 버전에 과도한 추상화나 서버 아키텍처를 도입하지 마라.

## 게임의 장기 비전
GuildMaster는 2D 탑다운 현대식 고품질 픽셀 아트 기반의 판타지 길드 운영 RPG다.
플레이어는 군주이자 길드마스터다. 군주와 길드원 4명으로 기본 모험 파티를 구성해 실시간 사냥·던전·의뢰를 수행한다. 그 외 길드원은 군주의 운영 방침에 따라 단련, 사냥, 던전 파견, 길드 의뢰, 거점 방어를 자동 수행한다.
게임은 소규모 5명으로 시작해 여관·사냥터·던전·이벤트에서 모험가를 스카우트하며 성장한다. 길드 명성이 높으면 우수한 인재를 더 낮은 보수로 영입할 수 있고, 명성이 낮으면 높은 보수를 제시해도 거절당할 수 있다.
세계의 성은 수가 한정되어 있으며, 마을을 무한히 확장하는 것이 아니라 AI 경쟁 길드와 공성전을 벌여 성을 빼앗는 것이 장기 목표다. 초기 게임은 싱글플레이이며 온라인 길드전은 향후 확장 가능성만 고려한다.

## 확정된 핵심 기획
- 시작 구성: 군주 1명 + 초기 길드원 약 4명.
- 기본 파티: 군주 1명 + 길드원 4명.
- 길드 규모: 초기 기준 최대 50명(설정값으로 조정 가능).
- 일반 길드원 직업: 탱커, DPS, 힐러, 마법사로 고정.
- 군주: 독립 캐릭터. 고정 직업 없음. 능력치 직접 분배 + 공격/마법/방어/지원 스킬 트리로 성장.
- 길드원 영입: 여관, 사냥터, 던전, 마을 이벤트 등에서 스카우트.
- 영입 조건: 레벨, 능력치, 스킬, 특성, 길드 명성, 계약금/정기 보수 영향을 받음.
- 명성 효과: 명성이 높으면 우수 인재가 찾아오거나 더 적은 보수로 영입 가능. 낮으면 돈을 많이 줘도 일부 인재는 거절.
- 길드원 성장: 경험치와 레벨. 기본 스킬은 자동 습득, 일부 특화 스킬은 플레이어 선택, 희귀 스킬은 특별 훈련·던전·보스·이벤트 등으로 획득.
- 길드원 활동: 단련(골드 수입 없이 경험치), 사냥(경험치·골드·재료), 던전(아이템), 의뢰(성공 시 골드/보상), 거점 방어.
- 단련 효율: 후반 레벨로 갈수록 같은 시간 대비 성장 효율 감소.
- 시간 시스템: 군주가 참여하는 전투는 실시간, 다른 길드원의 활동은 시간 경과 기반 자동 진행.
- 경제: 정기 유지비 + 활동 성과 보상. 초기에는 충성도·사기·불만·탈퇴 시스템 없음.
- 거점 습격: 몬스터가 골드·공용 아이템·시설 등을 노릴 수 있음. 일반 습격은 자동 방어, 대규모 습격은 군주 직접 참여 가능, 보스급 침공은 특별 실시간 전투.
- 거점/마을 성장은 제한적이며 길드 운영을 지원하는 역할만 한다.
- 성은 한정된 자산이며 공성전으로 소유권이 바뀐다. 초기에는 AI 길드가 경쟁자다.
- 아트 방향: 2D 탑다운 현대식 고품질 픽셀 아트. 단순 색상 도형은 최종 아트로 사용하지 않는다.

## 이번 작업의 우선 범위: Phase 2
기존 Phase 2 목표가 아직 구현되지 않았거나 미완성인 경우 아래 항목을 우선 안정화하라.
1. 기본 사냥 전투 루프.
2. 최소 3종 이상의 몬스터. 몬스터별 HP, 공격력, 이동 속도/행동 특성을 차별화.
3. 몬스터가 플레이어/파티를 추적하고 공격하는 동작.
4. 몬스터와 캐릭터의 HP 표시, 피격 효과, 공격 이펙트.
5. 몬스터 처치 시 경험치와 골드 획득.
6. 군주/플레이어 캐릭터 레벨업 및 공격력·HP 성장.
7. 레벨업 알림과 현재 레벨, HP, XP 바, 골드, 처치 수 등 UI 표시.
8. 플레이어 HP가 0이 되었을 때 패배/전투불능 상태 처리.
9. PC 입력과 기존 모바일 터치 입력 유지.
10. 기존 프로젝트의 시각 스타일을 존중하면서 고품질 픽셀 아트 방향으로 개선.

## 구현 지침
- 먼저 현재 코드에서 플레이어, 몬스터, 전투, 경험치, 골드, UI, 입력 처리의 위치를 파악하라.
- 이미 구현된 기능은 재사용하고 중복 시스템을 만들지 마라.
- 캐릭터와 몬스터의 능력치, 보상, 레벨업 경험치 곡선은 코드 곳곳에 하드코딩하지 말고 데이터/설정으로 분리하라.
- 전투 계산과 시각 효과/UI를 가능한 한 분리하라.
- 나중에 군주와 일반 길드원을 구분할 수 있도록 캐릭터 데이터에 역할/직업/레벨/능력치/스킬을 확장 가능한 형태로 둔다. 단, 이번 단계에서 전체 길드 관리 화면을 만들 필요는 없다.
- 전투 보상은 추후 군주 파티와 자동 파견 활동 양쪽에서 재사용할 수 있는 형태로 설계하되, 현재 범위에서는 실시간 기본 전투에 집중한다.
- 저장/불러오기가 이미 있다면 기존 저장 데이터와 호환성을 유지한다. 데이터 구조를 변경해야 한다면 기본값과 마이그레이션을 제공한다.
- 임시 도형은 디버깅에만 사용하고, 최종 표시에는 일관된 픽셀 아트 스프라이트와 애니메이션을 사용한다. 아트 에셋을 새로 만들 수 없는 경우 에셋 요구 목록과 임시 대체 상태를 명확히 보고한다.

## 작업 절차
1. 프로젝트 구조 및 현재 기능 조사.
2. 현재 구현 상태를 완료/미완료/오류로 정리.
3. 기존 기능을 보존하는 최소 변경 계획 제시.
4. Phase 2 범위만 구현.
5. 실행 및 플레이 테스트.
6. 키보드/마우스와 기존 터치 입력 테스트.
7. 몬스터 3종 이상, 보상, 레벨업, 패배 상태 검증.
8. 변경 파일과 주요 변경 사항, 테스트 결과, 미완료 사항을 보고.

## 완료 보고 형식
- 구현 완료 항목
- 미완료 항목 및 이유
- 수정한 파일 목록
- 실행/테스트 방법
- 발견된 버그 또는 제한 사항
- 다음 Phase에 권장하는 작업

중요: 장기 비전은 방향을 잡기 위한 기준이다. 이번 작업은 기존 프로토타입의 Phase 2를 안정화하는 데 집중하고, 아직 결정되지 않은 세부 수치나 규칙은 임의로 확정하지 말고 설정값 또는 임시값으로 분리하라.
